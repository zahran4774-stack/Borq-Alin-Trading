# نظام بروق العين للتجارة — محاسبة ومبيعات وصيانة (فرعان)

Next.js 14 + Supabase (PostgreSQL + RLS). واجهة عربية RTL، تعمل أونلاين من أي جهاز.

## ما يشمله
- **نقطة بيع (POS)**: باركود/بحث/IMEI، خصم، ضريبة 5%، دفع مجزأ (نقد/بطاقة/تحويل)، بيع آجل لعميل مسجل.
- **طباعة**: فاتورة A4 ضريبية، إيصال حراري 80mm، إيصال استلام صيانة بالشروط، كشف حساب، التقارير.
- **مشتريات** بأرقام IMEI، **مخزون لكل فرع**، **تحويل بين الفرعين**، رصيد افتتاحي وجرد.
- **صيانة**: استلام جهاز، عربون، تشخيص، قطع، حالات، تسليم وفوترة، إلغاء مع رد العربون.
- **محاسبة قيد مزدوج**: ميزان مراجعة، قائمة دخل، مركز مالي، ضريبة القيمة المضافة، مقارنة الفروع، مبيعات حسب التصنيف، أعمار الذمم، تقييم المخزون، قيود يدوية، إقفال فترات.
- **صلاحيات**: مدير، محاسب، مشاهد، مدير فرع، كاشير، فني. مستخدمو الفرع يرون فرعهم فقط (مفروض من قاعدة البيانات).

## تنبيهات المتأخرين عن السداد
- جرس 🔔 في الشريط العلوي يعرض عدد العملاء المتأخرين أكثر من 30 يوماً، وبطاقة تحذير في لوحة التحكم.
- صفحة «المتأخرون عن السداد»: قائمة بالعميل والمبلغ وأيام التأخير، مع زر واتساب برسالة تذكير جاهزة (بلغة الواجهة) واتصال وكشف حساب وتصدير وطباعة.
- يمكن تغيير المدة (7 إلى 90 يوماً) وعرض مستحقات الموردين المتأخرة علينا.
- التأخير يُحسب من تاريخ الاستحقاق، أو تاريخ الفاتورة إن لم يوجد استحقاق. العميل النقدي مستثنى.

## اللغة (عربي / English)
- زر 🌐 في أعلى الصفحة (وفي صفحة الدخول والطباعة) يبدّل اللغة والاتجاه (RTL/LTR) ويُحفظ اختيارك في المتصفح.
- الترجمة قاموس في `src/lib/i18n-dict.ts` (عربي ← إنجليزي). لإضافة أو تعديل أي ترجمة عدّل الأزواج هناك.
- الفاتورة المطبوعة تتبع لغة الواجهة؛ وتظهر اسم المنتج بالإنجليزية إن أدخلته في حقل «الاسم بالإنجليزية» بصفحة المنتجات.
- النصوص التي تكتبها أنت (أسماء العملاء، الملاحظات…) لا تُترجم، وتبقى كما أُدخلت.

## التشغيل المحلي
```bash
npm install
cp .env.example .env.local   # المفاتيح العامة مضبوطة مسبقاً
npm run dev                  # http://localhost:3000
```

## أول استخدام
1. افتح `/login` ثم رابط «إعداد النظام لأول مرة» (أو `/setup`) وأنشئ حساب المدير — أول حساب يصبح مدير تلقائياً.
2. إن طلب Supabase تأكيد البريد: من لوحة Supabase → Authentication → Providers → Email عطّل *Confirm email* (أو أكّد الحساب يدوياً).
3. **بعد إنشاء المدير عطّل التسجيل العام**: Authentication → Sign In / Providers → عطّل *Allow new users to sign up*.
4. الإعدادات ← بيانات المنشأة: أدخل الرقم الضريبي (VATIN) والسجل التجاري والهاتف، وحدّث اسم وعنوان وهاتف كل فرع.
5. الإعدادات ← المستخدمون: أنشئ الكاشير والمدراء (يتطلب `SUPABASE_SERVICE_ROLE_KEY`، انظر أدناه).
6. أدخل المنتجات، ثم الرصيد الافتتاحي من «المخزون ← رصيد افتتاحي / تسوية» لكل فرع.

## النشر (Vercel)
1. ارفع المجلد إلى GitHub واستورده في Vercel.
2. متغيرات البيئة:
   - `NEXT_PUBLIC_SUPABASE_URL` = `https://byhkwkltpyugrnitfmep.supabase.co`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` = المفتاح العام (publishable) الموجود في `.env.example`
   - `SUPABASE_SERVICE_ROLE_KEY` = من Supabase → Project Settings → API Keys (secret). **سري — لا تضعه في المتصفح أو GitHub.**
3. في Supabase → Authentication → URL Configuration أضف رابط الموقع.

## قاعدة البيانات
مشروع Supabase `al-ain-trading-accounting` مُجهّز بالكامل (الجداول، الدوال، سياسات RLS، الحسابات، الفرعان B1/B2). مجلد `supabase/migrations` سجل للتعديلات المطبقة (001–007) وهي تُبنى فوق مخطط المحاسبة الأساسي الموجود في المشروع، وليست كافية وحدها لإنشاء مشروع جديد من الصفر.
كل العمليات المالية والمخزنية تمر عبر دوال RPC محمية بالدور والفرع؛ الواجهة لا تكتب في جداول الفواتير والقيود مباشرة.
**النسخ الاحتياطي**: فعّل Point-in-Time Recovery أو نسخاً يومية من Supabase (خطة Pro) قبل التشغيل الفعلي.

## ملاحظات وحدود يجب معرفتها
- الأسعار تُدخل **قبل الضريبة** والضريبة تُضاف (5% افتراضياً). راجع المتطلبات الرسمية للفاتورة الضريبية في عُمان والرقم الضريبي قبل الاعتماد.
- لا يوجد مرتجع جزئي: الإلغاء يعكس الفاتورة كاملة (قيد + مخزون + دفعات) ثم تُصدر فاتورة جديدة.
- متوسط التكلفة المرجح يُحسب تلقائياً ولا يُعدّل يدوياً؛ الكاشير لا يرى التكلفة في الواجهة لكن عمود التكلفة قابل للقراءة تقنياً عبر الـAPI للمستخدمين المسجلين.
- التحويل بين الفروع فوري (بدون حالة «في الطريق»).
- قطع الغيار ذات IMEI تُباع بفاتورة بيع مستقلة وليس داخل أمر الصيانة.
- إقفال الفترة (الإعدادات ← إقفال الدفاتر) يمنع أي قيد بتاريخ قبل التاريخ المحدد.
- الطباعة الحرارية: اختر الطابعة وحجم الورق 80mm ودع الهوامش «بلا» في نافذة الطباعة.
